# Per-exercise progress statistics

Researched 22 October 2026 before implementation. Scope: give every exercise in the library a simple, coherent progress view, including week-by-week recorded weight and other useful statistics.

## Evidence and confidence

This review uses official product documentation and Auctus's source model. It establishes patterns used by comparable applications, not scientific proof that a chart or metric improves training. Recommendations and data-handling choices below are our design inferences. No training prescription is implied.

- **Hevy:** selecting an exercise from the library opens metric-selectable graphs, records, and a history of its workouts. Weighted exercise graphs include heaviest weight, estimated maximum, set/session volume, and reps. Bodyweight and assisted exercise graphs instead emphasize best-set and session reps. Session links expose the original context. [Official exercise-library tracking guide](https://help.hevyapp.com/hc/en-us/articles/35382889578135-Exercise-Performance-Tracking-in-Library-Weight-Bodyweight-Cardio-and-Duration-Based-Exercises)
- **Hevy's records:** distinguishes heaviest weight, set volume, session volume, and a table of heaviest weight at each exact repetition count. It also describes more reps at a given weight as a record. These comparisons preserve more context than a weight-only headline. [Official records guide](https://help.hevyapp.com/hc/en-us/articles/35649367857175-Personal-Records-PRs-and-Set-Records-Explained-How-They-Work-in-the-Hevy-App)
- **Strong:** its exercise detail groups history, charts, and records; records include best performances by rep count. This help page was last updated in 2021, so exact contemporary placement has lower confidence. [Official exercise-detail guide](https://help.strongapp.io/article/237-about-exercise-detail)
- **Strong:** its focus metric compares an exercise with its previous performance and allows volume or reps among the choices. This supports explicit, like-for-like labels and previous-session context. [Official focus-metric guide](https://help.strongapp.io/article/226-focus-metric)
- **Fitbod:** its February 2026 redesign pairs selectable metric/timeframe charts with exact logged weights and reps in recent results. It explains that users found the old projected-one-rep-max terminology confusing. This supports readable labels and an inspectable log alongside analytics. [Official exercise-history announcement](https://fitbod.me/blog/exercise-history-and-records/)
- **Fitbod:** defines volume, heaviest weight, and most reps as separate metrics; its estimated strength includes algorithmic adjustments. Auctus should not imitate those adjustments without the requisite model. [Official metrics reference](https://help.fitbod.me/hc/en-us/articles/12732749777047-Fitbod-Metrics-Records)
- **Estimated maxima:** Hevy explicitly calls these estimates rather than confirmed lifts, notes that formulas differ, and warns that higher-rep estimates can be less accurate. Hevy uses a rep-percentage lookup, not Auctus's existing Epley calculation. [Official estimated-1RM explanation](https://help.hevyapp.com/hc/en-us/articles/36954464726167-Understanding-Your-Estimated-One-Rep-Max-1RM-in-Hevy)

## Recommended hierarchy

1. **Open progress from every library exercise.** Keep edit/archive actions separate. An untrained exercise gets a genuine empty state; an archived exercise's existing history remains accessible wherever the app permits archive browsing.
2. **Lead with one weekly chart.** Default to recorded weight when positive load exists. Pair each week's heaviest working set with its actual reps, for example `40 kg × 8`. Let users switch to logged volume or reps without showing several competing chart scales. Offer a short recent window and a longer/all-time view when practical.
3. **Show a few clear facts:** heaviest recorded working set with reps/date, number of completed sessions, working sets, and last trained date. For zero-load history, prioritize most reps in one set and total reps rather than an empty kilogram record.
4. **Add exact comparisons.** A compact best-weight-by-rep-count table or most-reps-at-each-recorded-weight table answers whether recorded performance improved under a comparable load or rep count. A heavier single and a lighter ten-rep set should not be ranked as universally better/worse. Clearly label change as change in the specific metric, not a strength verdict.
5. **Keep sessions nearby.** Recent sessions show date, top recorded set, working sets/reps/volume and a link to original history. The same progress view can replace the older history-only progress presentation so definitions do not drift.

## Auctus calculation contract

Verified against `src/domain/types.ts`, `src/domain/metrics.ts`, `src/domain/dashboard.ts`, `src/domain/calendar.ts`, `src/domain/equipment.ts`, and the removal semantics in `src/server/sessions.ts`.

- Compare stable `exercise_id`, never names. Aggregate repeated appearances of that exercise within a workout into one session. Renaming should not reset history; different exercise IDs should not merge.
- Use completed workouts and completed sets with actual values. Exclude pending/skipped sets, abandoned sessions, and prefills. Auctus deliberately retains completed work when an exercise or set is removed from the plan: removal preserves completed status, while unfinished sets become skipped. Therefore `removed_at` alone must not erase completed records from statistics; keep this consistent with existing history and dashboard accounting. Warm-up sets remain inspectable in history but should be excluded from metrics labelled **working** sets, reps, load, or volume. Existing general dashboard totals include warm-ups, so explain this distinction instead of silently changing unrelated totals.
- **Heaviest recorded set:** maximum nonnegative actual weight among eligible sets with positive actual reps; break ties by reps. Display load and reps together. Zero kilograms is a real logged value; missing weight is not zero. Do not manufacture records for an empty dataset.
- **Working volume:** sum `(actual_grams / 1000) × actual_reps` for valid completed working sets. Label it logged weight × reps. Do not automatically double dumbbell/unilateral values or add bodyweight; Auctus has no established information to do that. Volume describes recorded work, not physiological adaptation.
- **Reps and sets:** count completed working sets and sum actual positive reps. These stay useful without positive loads. A maximum-reps record should display its recorded load when available, since 15 reps at one load and 15 at another are different performances.
- **Weekly attribution:** keep the existing dashboard's assigned training-week accounting (`week_id`, falling back to the workout start's training week) for coherence. Auctus's week resets Monday 03:00 Europe/Amsterdam. Label this as a training week, since a workout performed later can remain attributed to its original assigned week. Preserve the actual date alongside session results so it is clear when the exercise was performed. Mark the current week in progress and use existing timezone-aware utilities across daylight-saving changes.
- **Missing weeks:** no recorded set means a gap/null for weight or estimates, never a fall to zero. Weekly activity totals can be zero and labelled no logged work. Do not connect a line through missing weeks as if an observation exists. Do not carry the previous weight forward.
- **Comparisons:** identify the dates/periods being compared. An unfinished week should not receive a decline verdict against an entire previous week. One observation is a starting point; avoid percentage change against zero. Prefer neutral differences in the named quantity.
- **Estimated maximum is optional, secondary.** Existing `estimatedMax` uses `kg × (1 + reps / 30)` for 2–10 reps, actual kg for one rep, and excludes zero load/out-of-range reps. If exposed, retain an explicit estimated label and formula/eligibility explanation. This is an existing Auctus convention, not Hevy's formula, and does not establish a lift the user performed.
- **Unknown exercise type:** Auctus records equipment but does not classify bodyweight, assisted, or timed exercise types. Never infer the type from an exercise name or assume that greater machine assistance means better performance. Use neutral recorded-weight language. Do not add bodyweight-adjusted loads, recovery, percentiles, muscle-growth scores, or duration records unsupported by the input model.

Charts need visible units and dates, keyboard-operable controls, and exact values available without hover or color. A clear empty state and one-session state are part of the feature, not exceptions to hide with sample data.
